# Технический обзор baking_calc

Дата актуализации: 9 сентября 2026.

## Текущее состояние

Проект остаётся статическим сайтом без backend и сборки. Готовые пользовательские инструменты:

| Инструмент | Страница | Состояние |
| --- | --- | --- |
| BakeCalc | `bakecalc.html` | Рабочий пересчёт рецепта, форм и себестоимости |
| CreamCalc | `creamcalc.html` | Рабочий расчёт крема для прослоек и покрытия |
| PortionCalc | `portioncalc.html` | Рабочий расчёт размера торта по гостям и геометрии кусочка |
| GelatinCalc | `gelatincalc.html` | Пересчёт Bloom и гидратации желатина |
| Конвертер | — | Запланирован |
| Цена продажи | — | Запланирована |

Все готовые страницы имеют возврат в каталог. Незавершённые карточки на главной не являются фиктивными ссылками `#`.

## Архитектура

Новые и переработанные калькуляторы используют разделение чистой математики и браузерного контроллера:

- `js/bakecalc-math.js` + legacy `js/app.js` и слой надёжности;
- `js/creamcalc-math.js` + `js/creamcalc.js`;
- `js/portioncalc-math.js` + `js/portioncalc.js`;
- `js/gelatincalc-math.js` + `js/gelatincalc.js`.

Чистые модули можно проверять в Node без DOM. Состояния инструментов хранятся в отдельных ключах `localStorage`; сохранённые вычисленные результаты не должны считаться доверенным источником истины.

## Исправленные исторические проблемы

В ходе предыдущих PR закрыты основные дефекты исходного BakeCalc:

- одностороннее использование высоты больше не подменяет отсутствующую высоту единицей;
- неполная себестоимость не должна выглядеть как гарантированно полная;
- несовместимые единицы не превращаются молча в нулевую стоимость;
- результат скрывается после изменения исходных параметров;
- данные `localStorage` нормализуются;
- исправлена устойчивость копирования и внешних иконок;
- добавлены автоматические расчётные тесты и CI.

PortionCalc после нескольких UX-итераций теперь использует модель «форма → геометрия реального кусочка → гости и запас». Для круглой формы кусочек оценивается как клин, для прямоугольной — как прямоугольник; пользователь не задаёт технические параметры самого искомого торта.

## Проверки

CI состоит из двух уровней.

### Unit и DOM-contract

```sh
node --test tests/*.test.cjs
```

Проверяются формулы, валидация, восстановление состояния и критические связи между HTML и контроллерами.

### Browser smoke

GitHub Actions поднимает статический HTTP-сервер и запускает Chromium через Playwright. Для каждого готового инструмента выполняется минимальный пользовательский сценарий:

1. открыть страницу;
2. выполнить типовой расчёт;
3. дождаться видимого блока результата;
4. убедиться, что ключевое значение результата непустое;
5. убедиться, что страница не выбросила необработанную JavaScript-ошибку.

Эта проверка добавлена после случая, когда математические Node-тесты были зелёными, но несовпадение HTML и закэшированной версии JavaScript делало PortionCalc неработоспособным в браузере.

## GelatinCalc

GelatinCalc использует приближённый пересчёт силы Bloom:

```text
m₂ = m₁ × √(B₁ / B₂)
```

где `m₁` и `B₁` относятся к желатину из рецепта, а `B₂` — к имеющемуся желатину. Интерфейс явно предупреждает, что это ориентир, а не гарантия идентичной текстуры.

Гидратация считается отдельно по пользовательскому отношению воды:

```text
вода = m₂ × ratio
желатиновая масса = m₂ + вода
```

## Оставшиеся технические риски

1. **CDN-зависимости.** Tailwind, шрифт Inter и Lucide загружаются с внешних CDN. При сетевом сбое оформление может деградировать; часть старого BakeCalc всё ещё содержит legacy-вызовы внешних библиотек.
2. **BakeCalc остаётся наиболее legacy-страницей.** Большая часть DOM-логики живёт в `js/app.js` с глобальным состоянием и inline-обработчиками. Математика уже отделена частично, но полная миграция на архитектуру CreamCalc/PortionCalc пока не выполнена.
3. **Нет полноценного визуального regression testing.** Browser smoke проверяет работоспособность, но не сравнивает внешний вид по скриншотам.
4. **Нет backend.** Это осознанно и нормально для текущих калькуляторов, но будущие аккаунты, синхронизация рецептов или серверная монетизация потребуют другой архитектуры.
5. **Рекламные контейнеры и Метрика не равны рекламной интеграции.** Код Метрики существует, но полноценная RTB-интеграция должна рассматриваться отдельно от калькуляторной логики.

## Следующий продуктовый этап

После стабилизации GelatinCalc логичный следующий инструмент — конвертер единиц. Конвертацию массы и объёма следует разрешать только через явно заданную плотность ингредиента; универсальное равенство `1 мл = 1 г` использовать нельзя.
