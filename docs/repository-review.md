# Технический обзор baking_calc

Дата актуализации: 9 сентября 2026.

## Текущее состояние

Проект остаётся статическим сайтом без backend и обязательной сборки. Исходная сетка из шести пользовательских инструментов полностью реализована:

| Инструмент | Страница | Состояние |
| --- | --- | --- |
| BakeCalc | `/pereschet-recepta/` | Пересчёт рецепта, форм и себестоимости |
| CreamCalc | `/raschet-krema-dlya-torta/` | Расчёт крема для прослоек и покрытия |
| PortionCalc | `/razmer-torta-po-gostyam/` | Размер торта по гостям и геометрии кусочка |
| GelatinCalc | `/pereschet-zhelatina-bloom/` | Пересчёт Bloom и гидратации желатина |
| ConverterCalc | `/konverter-ingredientov/` | г/кг/мл/л и масса ↔ объём через плотность |
| PriceCalc | `/raschet-ceny-torta/` | Цена продажи, работа, комиссия, прибыль и маржа |

Все страницы имеют возврат в каталог. На главной нет карточек-заглушек «Скоро».

## Архитектура

Переработанные калькуляторы разделяют чистую математику и браузерный контроллер:

- BakeCalc: `js/bakecalc-math.js` + `js/bakecalc-state.js` + `js/bakecalc-view.js` + `js/bakecalc-events.js` + контроллер `js/app.js`;
- `js/creamcalc-math.js` + `js/creamcalc.js`;
- `js/portioncalc-math.js` + `js/portioncalc.js`;
- `js/gelatincalc-math.js` + `js/gelatincalc.js`;
- `js/convertercalc-math.js` + `js/convertercalc.js`;
- `js/pricecalc-math.js` + `js/pricecalc.js`.

BakeCalc больше не использует compatibility/monkey-patch слой: `js/bakecalc-hardening.js` удалён. Контроллер обращается к `BakeCalcMath` напрямую, view отвечает за DOM, events — за делегированные события, а state — за нормализованное сохранение.

Чистые модули проверяются в Node без DOM. Состояния инструментов хранятся в отдельных ключах `localStorage`; вычисленные результаты не используются как доверенный источник истины.

## Интеграция BakeCalc → PriceCalc

После успешного расчёта полной себестоимости BakeCalc показывает кнопку «Рассчитать цену продажи». Переход передаёт в PriceCalc только числовые исходные затраты:

- стоимость ингредиентов;
- упаковку/коробку;
- остальные дополнительные расходы.

Расходы с названием, содержащим «упаковка» или «коробка», автоматически относятся к полю упаковки PriceCalc; остальные дополнительные расходы попадают в «Прочие расходы». Работа, комиссия и целевая прибыль/маржа остаются настройками PriceCalc.

Передача выполняется через прозрачные query-параметры. PriceCalc принимает только ожидаемые неотрицательные числовые значения, сохраняет импортированные поля в своё состояние и затем очищает query из адресной строки. Если себестоимость BakeCalc неполная, переход в PriceCalc не предлагается.

## SEO-фундамент

Добавлен общий `js/seo.js`, который централизованно задаёт для каталога и всех шести калькуляторов уникальные title/description, canonical URL, Open Graph, Twitter metadata и JSON-LD.

Публичная база canonical URL: `https://konditercalc.ru/`. В репозитории есть `CNAME` для `konditercalc.ru`; критические SEO-метаданные находятся непосредственно в HTML, а `robots.txt` и `sitemap.xml` используют тот же основной домен.

Также добавлены `robots.txt`, `sitemap.xml`, unit-проверка SEO-конфигурации и browser-smoke canonical/JSON-LD.

## Проверки

CI состоит из двух уровней.

### Unit и DOM-contract

```sh
node --test tests/*.test.cjs
```

Проверяются формулы, валидация, восстановление состояния, DOM-контракты, границы BakeCalc-модулей и SEO-файлы.

### Browser smoke

GitHub Actions поднимает статический HTTP-сервер и запускает системный Chrome через Playwright. Для каждого инструмента выполняется типовой расчёт, проверяется результат, отсутствие необработанных JavaScript-ошибок, canonical и JSON-LD.

Дополнительно проверяются делегированные события BakeCalc и реальный путь:

```text
BakeCalc → демо-рецепт → расчёт себестоимости → PriceCalc → проверка перенесённых расходов
```

## Исправленные исторические проблемы

В предыдущих PR закрыты основные дефекты исходного BakeCalc и PortionCalc:

- одностороннее использование высоты больше не подменяет отсутствующую высоту единицей;
- неполная себестоимость не выглядит гарантированно полной;
- несовместимые единицы не превращаются молча в нулевую стоимость;
- результат скрывается после изменения параметров формы;
- данные `localStorage` нормализуются;
- исправлены копирование, внешние иконки и некорректный DOM-селектор BakeCalc;
- состояние, DOM и события BakeCalc разделены;
- inline JavaScript удалён;
- compatibility/monkey-patch слой BakeCalc удалён;
- PortionCalc использует модель «форма → геометрия реального кусочка → гости и запас»;
- CI использует системный Chrome и не зависит от установки браузера через нестабильный apt-репозиторий Google.

## Оставшиеся технические риски

1. **Глобальный API BakeCalc можно ещё сократить.** Основная архитектурная задолженность уже закрыта, но `js/app.js` пока остаётся обычным browser-script с функциями верхнего уровня.
2. **SEO metadata добавляются общим JavaScript-слоем.** После появления сборки лучше генерировать critical meta/canonical/JSON-LD непосредственно в HTML.
3. **Нет полноценного visual regression testing.** Browser smoke проверяет работоспособность, но не внешний вид по эталонным скриншотам.
4. **Нет backend.** Для текущих калькуляторов это нормально; аккаунты и синхронизация потребуют другой архитектуры.
5. **Монетизация ещё не интегрирована полностью.** Метрика не равна рекламной RTB-интеграции.

## Следующий этап продукта

После завершения основного технического рефакторинга BakeCalc приоритет смещается с внутренней уборки на продукт:

1. добавить продуктовые события аналитики;
2. подготовить стабильные рекламные места без layout shift;
3. по данным использования улучшать SEO-контент и внутренние связи;
4. отдельно решить, нужен ли visual regression testing до дальнейших крупных UI-изменений.

## Миграция с Tailwind

Runtime Tailwind CDN и конфигурационные блоки удалены со всех публичных страниц. Пакет Tailwind и сборка Tailwind не используются. Текущие utility-подобные классы обслуживаются локальным `css/utilities.css`, поэтому GitHub Pages по-прежнему публикует обычный статический сайт без этапа сборки. CI проверяет отсутствие Tailwind CDN/config/package.
