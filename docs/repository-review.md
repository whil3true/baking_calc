# Технический обзор baking_calc

Дата актуализации: 9 сентября 2026.

## Текущее состояние

Проект остаётся статическим сайтом без backend и обязательной сборки. Исходная сетка из шести пользовательских инструментов теперь полностью реализована:

| Инструмент | Страница | Состояние |
| --- | --- | --- |
| BakeCalc | `bakecalc.html` | Пересчёт рецепта, форм и себестоимости |
| CreamCalc | `creamcalc.html` | Расчёт крема для прослоек и покрытия |
| PortionCalc | `portioncalc.html` | Размер торта по гостям и геометрии кусочка |
| GelatinCalc | `gelatincalc.html` | Пересчёт Bloom и гидратации желатина |
| ConverterCalc | `convertercalc.html` | г/кг/мл/л и масса ↔ объём через плотность |
| PriceCalc | `pricecalc.html` | Цена продажи, работа, комиссия, прибыль и маржа |

Все страницы имеют возврат в каталог. На главной больше нет карточек-заглушек «Скоро».

## Архитектура

Переработанные калькуляторы разделяют чистую математику и браузерный контроллер:

- `js/bakecalc-math.js` + legacy `js/app.js` и слой надёжности;
- `js/creamcalc-math.js` + `js/creamcalc.js`;
- `js/portioncalc-math.js` + `js/portioncalc.js`;
- `js/gelatincalc-math.js` + `js/gelatincalc.js`;
- `js/convertercalc-math.js` + `js/convertercalc.js`;
- `js/pricecalc-math.js` + `js/pricecalc.js`.

Чистые модули проверяются в Node без DOM. Состояния инструментов хранятся в отдельных ключах `localStorage`; сохранённые вычисленные результаты не используются как источник истины.

## PriceCalc

PriceCalc строит цену продажи из базовой себестоимости:

```text
базовая_себестоимость = ингредиенты + упаковка + прочие расходы + время × ставка_в_час
```

Поддерживаются два режима цели:

1. **Желаемая маржа, %** — цена решается так, чтобы после комиссии прибыль составляла заданную долю от цены продажи.
2. **Желаемая прибыль, ₽** — цена решается так, чтобы после комиссии сохранить указанную прибыль в рублях.

Комиссия считается от цены продажи. Маржа и наценка разделены:

```text
маржа = прибыль / цена_продажи × 100%
наценка = прибыль / базовая_себестоимость × 100%
```

Масса изделия и количество порций необязательны; при наличии рассчитываются цена за кг и цена за порцию.

## ConverterCalc

ConverterCalc намеренно не использует универсальное равенство `1 мл = 1 г`.

Прямые конверсии:

```text
1000 г = 1 кг
1000 мл = 1 л
```

Переход между массой и объёмом выполняется только через плотность в `г/мл`:

```text
объём = масса / плотность
масса = объём × плотность
```

Поле плотности скрывается, если пользователь переводит массу в массу или объём в объём.

## Проверки

CI состоит из двух уровней.

### Unit и DOM-contract

```sh
node --test tests/*.test.cjs
```

Проверяются формулы, валидация, восстановление состояния и критические связи между HTML и контроллерами. PriceCalc покрывает режим маржи, режим фиксированной прибыли, комиссию, стоимость труда, необязательные цену за кг/порцию и недопустимые значения.

### Browser smoke

GitHub Actions поднимает статический HTTP-сервер и запускает системный Chrome через Playwright. Для каждого готового инструмента выполняется минимальный пользовательский сценарий:

1. открыть страницу;
2. выполнить типовой расчёт;
3. дождаться видимого блока результата;
4. убедиться, что ключевое значение результата непустое;
5. убедиться, что страница не выбросила необработанную JavaScript-ошибку.

Browser smoke покрывает все шесть инструментов.

## Исправленные исторические проблемы

В предыдущих PR закрыты основные дефекты исходного BakeCalc и PortionCalc:

- одностороннее использование высоты больше не подменяет отсутствующую высоту единицей;
- неполная себестоимость не выглядит гарантированно полной;
- несовместимые единицы не превращаются молча в нулевую стоимость;
- результат скрывается после изменения исходных параметров;
- данные `localStorage` нормализуются;
- исправлена устойчивость копирования и внешних иконок;
- исправлен некорректный DOM-селектор BakeCalc, обнаруженный browser smoke;
- PortionCalc использует модель «форма → геометрия реального кусочка → гости и запас»;
- CI переведён на системный Chrome, чтобы не зависеть от нестабильного apt-репозитория Google при каждом запуске.

## Оставшиеся технические риски

1. **CDN-зависимости.** Tailwind, Inter и Lucide загружаются с внешних CDN. При сетевом сбое оформление может деградировать.
2. **BakeCalc остаётся наиболее legacy-страницей.** Большая часть DOM-логики живёт в `js/app.js` с глобальным состоянием и inline-обработчиками.
3. **Нет полноценного visual regression testing.** Browser smoke проверяет работоспособность, но не внешний вид по эталонным скриншотам.
4. **Нет backend.** Для текущих калькуляторов это нормально; аккаунты и синхронизация потребуют другой архитектуры.
5. **Монетизация ещё не интегрирована полностью.** Метрика не равна рекламной RTB-интеграции.

## Следующий этап продукта

Каталог калькуляторов завершён. Следующий приоритет стоит сместить с добавления новых инструментов на качество продукта:

2. устранение зависимости от runtime Tailwind CDN и фиксация внешних библиотек;
3. рефакторинг legacy BakeCalc;
4. аналитика использования инструментов;
5. подготовка и тестирование рекламных мест;
6. интеграция между инструментами, прежде всего передача себестоимости из BakeCalc в PriceCalc.
