# BakeCalc

Статические бесплатные инструменты для кондитеров. Серверная часть и сборка для самого сайта не нужны; страницы совместимы с GitHub Pages в подпапке `/baking_calc/`.

## Инструменты

- `index.html` — каталог.
- `bakecalc.html` — пересчёт рецепта под другую форму и себестоимость.
- `creamcalc.html` — крем для прослоек, верха и боков торта.
- `portioncalc.html` — рекомендуемый размер торта по количеству гостей и геометрии одного кусочка.
- `gelatincalc.html` — пересчёт количества желатина между разной силой Bloom и вода для гидратации.
- `convertercalc.html` — перевод г/кг/мл/л, включая массу ↔ объём через плотность.
- `pricecalc.html` — расчёт цены продажи с учётом себестоимости, труда, комиссии, прибыли и маржи.

В шапке и внизу каждого готового инструмента есть ссылка «На главную». Для новых страниц используйте `<a href="index.html" class="home-link">← На главную</a>`.

## PriceCalc

PriceCalc собирает цену продажи из реальных составляющих:

- ингредиенты;
- упаковка;
- прочие прямые расходы;
- время работы и стоимость часа;
- комиссия от цены продажи;
- желаемая маржа или желаемая прибыль в рублях.

Базовая себестоимость:

```text
себестоимость = ингредиенты + упаковка + прочие расходы + время × ставка_в_час
```

При расчёте по марже цена подбирается так, чтобы после комиссии прибыль составляла заданную долю от цены продажи. При расчёте по прибыли в рублях указанная прибыль сохраняется после комиссии.

Калькулятор отдельно показывает:

```text
маржа = прибыль / цена_продажи × 100%
наценка = прибыль / себестоимость × 100%
```

Это разные показатели и в интерфейсе они не смешиваются. Масса изделия и количество порций необязательны; если они указаны, дополнительно выводится цена за кг и цена за порцию.

Параметры сохраняются под ключом `pricecalc_state_v1`. Старый результат скрывается после изменения данных.

## ConverterCalc

Конвертер поддерживает четыре единицы: граммы, килограммы, миллилитры и литры.

- масса ↔ масса (`г ↔ кг`) переводится напрямую;
- объём ↔ объём (`мл ↔ л`) переводится напрямую;
- масса ↔ объём требует плотность ингредиента в `г/мл`.

Формулы для перехода между физическими величинами:

```text
объём = масса / плотность
масса = объём × плотность
```

Поле плотности показывается только тогда, когда оно действительно необходимо. Значение `1 г/мл` не считается универсальным: оно подходит воде и близким по плотности жидкостям, но для других ингредиентов нужна их фактическая плотность.

Параметры сохраняются под ключом `convertercalc_state_v1`. После изменения исходных данных старый результат скрывается. Есть кнопка обмена исходной и итоговой единицы и копирование результата.

## PortionCalc

Порядок работы соответствует реальной задаче пользователя:

1. Выберите форму торта. Круглая форма предполагает клиновидную нарезку, прямоугольная — сетку.
2. Задайте размеры одного реального кусочка. Для круга это длина клина и его ширина по внешнему краю; для прямоугольника — длина и ширина кусочка.
3. Укажите количество гостей и процент запаса.
4. Выполните расчёт.

Для круглого торта площадь одного клина оценивается как `длина × ширина / 2`. Для прямоугольного кусочка — `длина × ширина`. Количество порций увеличивается на запас. Из общей площади вычисляется диаметр круглого торта либо автоматически подбирается компактный целочисленный прямоугольник с минимальным избытком площади. Итоговые размеры округляются только вверх.

Высота торта намеренно не участвует в модели: PortionCalc отвечает за площадь нарезки. Реальная вместимость всё равно зависит от фактической техники нарезки.

Параметры сохраняются отдельно под ключом `portioncalc_state_v1`. Старый результат скрывается после любого изменения параметров.

## GelatinCalc

GelatinCalc решает две связанные задачи:

1. Пересчитывает массу желатина, если Bloom в рецепте отличается от Bloom имеющегося желатина.
2. Считает воду для гидратации и итоговую желатиновую массу по заданному отношению воды.

Используется приближённая формула:

```text
масса_вашего = масса_рецепта × √(Bloom_рецепта / Bloom_вашего)
```

Если ваш желатин слабее, его понадобится больше; если сильнее — меньше. Пересчёт не является физически точной гарантией одинаковой текстуры: состав продукта, кислотность, сахар, технология и конкретный желатин влияют на результат. Поэтому интерфейс явно помечает расчёт как ориентир.

Гидратация считается отдельно:

```text
вода = рассчитанный_желатин × отношение_воды
желатиновая_масса = желатин + вода
```

Отношение `1:5` задано по умолчанию только как рабочий пример и редактируется пользователем.

## CreamCalc

1. Укажите форму, размеры и высоту **собранного торта с прослойками, до внешнего покрытия**.
2. Укажите количество кремовых прослоек и их толщину. Для расчёта только покрытия задайте 0 прослоек.
3. Выберите покрытие верха и/или боков и задайте толщину.
4. Уточните плотность каждого крема и процент запаса. Нажмите «Рассчитать крем».

Размеры вводятся в сантиметрах, толщина — в миллиметрах, плотность — в г/мл. Поддерживаются точка и запятая. Плотность **1 г/мл — пример**, а не справочная характеристика любого крема. Чтобы определить свою, взвесьте 100 мл готового крема без учёта ёмкости и разделите вес на 100.

Выводятся вес для каждой части, запас и общий вес. Количество для приготовления округляется вверх до 10 г. Модель предполагает ровные слои; дно, ягодная начинка, бордюры и крупный декор не учитываются.

Параметры сохраняются под отдельным ключом `creamcalc_state_v1`; рецепт BakeCalc (`bakecalc_state`) не затрагивается. После редактирования параметров старый результат скрывается до следующего расчёта.

### Формулы CreamCalc

После перевода толщин в сантиметры: `A` — площадь торта, `H` — его высота, `s` — толщина боков, `t` — толщина верха.

- Круг: `A = πr²`; площадь оболочки `B = πs(2r + s)`.
- Прямоугольник: `A = L × W`; `B = 2s(L + W) + 4s²`.
- Прослойки: `V = A × толщина × количество`.
- Бока: `V = B × H`.
- Верх: `V = (A + B) × t`. При выключенных боках `B = 0`.
- Вес каждой части: `m = V × плотность`; общий запас: `сумма весов × процент / 100`.

## Разработка и проверка

Для локального запуска:

```sh
python3 -m http.server 8000
```

Откройте `http://localhost:8000/`.

### Быстрые тесты математики и DOM-контрактов

Нужен Node.js 18+:

```sh
node --test tests/*.test.cjs
```

### Реальные browser smoke-тесты

CI дополнительно запускает Chrome через Playwright. Smoke-сценарии открывают все готовые инструменты, выполняют типовой расчёт, проверяют появление результата и отсутствие необработанных JavaScript-ошибок страницы.

Локально их можно запустить после установки Playwright и доступного Chrome:

```sh
npm install --no-save playwright@1.55.0
python3 -m http.server 8000
node tests/browser-smoke.mjs
```

GitHub Actions запускает unit/DOM тесты и browser smoke как отдельные jobs. Merge имеет смысл делать только после зелёных проверок.

Чистая математика вынесена в `js/bakecalc-math.js`, `js/creamcalc-math.js`, `js/portioncalc-math.js`, `js/gelatincalc-math.js`, `js/convertercalc-math.js` и `js/pricecalc-math.js`. Контроллеры страниц отвечают за DOM, сохранение состояния, ошибки и копирование.

Tailwind, Inter и Lucide пока подключаются с CDN, поэтому исходное оформление зависит от сети. История технического аудита и текущее состояние: [docs/repository-review.md](docs/repository-review.md).
